# Исправления оплаты — что сделать после распаковки

## 1. Удалить старые файлы (переехали в пакет config)
- src/main/java/com/analytics/service/dto/YooKassaProperties.java
- src/main/java/com/analytics/service/services/YooKassaConfig.java

После замены: **Build → Rebuild Project** (или удали папку target), чтобы не осталось старых .class.

## 2. Секретный ключ — через переменную окружения
IntelliJ: Run → Edit Configurations → ServiceApplication → Environment variables:
    YOOKASSA_SECRET_KEY=test_....
Без ключа приложение теперь не стартует и прямо пишет, чего не хватает.
Старый ключ светился в файле и в переписке — выпусти новый в личном кабинете ЮKassa.

Если опять будет "connect timed out" — добавь в VM options:
    -Djava.net.preferIPv4Stack=true

## 3. ОБЯЗАТЕЛЬНО: почистить старые неоплаченные заказы
Теперь товар резервируется при создании заказа, а при отмене возвращается на склад.
Старые заказы создавались БЕЗ резерва — если их отменит фоновая сверка, остатки
завысятся. Удали их до запуска:

    docker exec -it akastore psql -U akauser -d akadb -c "DELETE FROM order_items WHERE order_id IN (SELECT id FROM orders WHERE status='PENDING_PAYMENT'); DELETE FROM orders WHERE status='PENDING_PAYMENT';"

## Что исправлено

Бэкенд
- Транзакции вынесены в OrderTxService: вызов @Transactional через this их игнорировал.
- HTTP к ЮKassa больше не выполняется внутри транзакции.
- Блокировка строки заказа (PESSIMISTIC_WRITE): webhook и опрос статуса не проведут оплату дважды.
- Платёж сверяется с заказом по данным самой ЮKassa: чужой платёж к заказу не привяжешь.
- Нет суммы в ответе ЮKassa → отказ (раньше проверка молча пропускалась).
- Доставка считается на сервере и входит в сумму оплаты; фронт показывает её через POST /orders/quote.
- Idempotence-Key = "order-<id>": повтор запроса не создаст второй платёж.
- После оплаты из корзины удаляются только оплаченные позиции, а не вся корзина.
- Резерв товара при создании заказа — нет продажи одной единицы двум покупателям.
- Неудачное создание платежа отменяет заказ и возвращает резерв.
- Фоновая сверка: зависшие платежи сверяются с ЮKassa, брошенные заказы отменяются.
- Webhook не доверяет телу уведомления: берёт только id платежа.
- Повторы одного товара в запросе склеиваются перед проверкой остатка.
- Чужой заказ → 403, сбой платёжного сервиса → 502, конфликт состояния → 409.
- Настройки ЮKassa в пакете config, ключ вне файла.

Фронтенд
- payment-return.html: закрыта XSS через orderId в ссылке; разбор 401/403/404;
  таймаут на каждый запрос и общий лимит 30 с; DELIVERED считается оплаченным;
  «Назад» не уводит на ЮKassa; aria-live; не залипает старый номер заказа.
- checkout.html: сумму показывает сервер; оформляются только отмеченные в корзине
  позиции; проверка параметров ссылки и телефона; экранирование данных.
- cart.html / main.html: «Оформить» и «Купить» передают ровно выбранные товары.
- login.html: после входа возвращает туда, откуда отправили (только свои страницы);
  покупателя больше не кидает в админку.

## Замечание
Если админ вручную ставит заказу статус CANCELLED, резерв не возвращается
на склад — это отдельная доработка AdminService.
